1. ინტერნეტი და IP Address

ინტერნეტი არის ერთმანეთთან დაკავშირებული კომპიუტერული ქსელების გლობალური
სისტემა. მისი საშუალებით მოწყობილობებს შეუძლიათ ინფორმაციის გაცვლა,
ვებსაიტების გახსნა, შეტყობინებების გაგზავნა და ონლაინ სერვისების გამოყენება

როგორ მუშაობს ინტერნეტი: 
1. მოწყობილობა აგზავნის მონაცემებს ქსელის საშუალებით
2. მონაცემები იყოფა პატარა ნაწილებად, რომლებსაც პაკეტები (Packets) ეწოდება
3. როუტერები პაკეტებს დანიშნულების ქსელამდე მისვლაში ეხმარება
4. დანიშნულების მოწყობილობა იღებს მონაცემებს და საჭიროების შემთხვევაში აერთიანებს მათ

IP Address არის რიცხვითი მისამართი, რომელიც ქსელში მოწყობილობის ან
ქსელური ინტერფეისის იდენტიფიცირებას ეხმარება. ის მონაცემებს სწორი დანიშნულებისკენ მიმართვაში ეხმარება

მაგალითები: IPv4: 192.168.1.10 - IPv6: 2001:db8::1

საჯარო IP მისამართი ინტერნეტში ქსელის იდენტიფიცირებისთვის გამოიყენება, ხოლო კერძო IP მისამართი ხშირად სახლის ან ოფისის ადგილობრივ ქსელში გამოიყენება


2. LAN, Router და Switch

LAN (Local Area Network) არის ლოკალური ქსელი, რომელიც მცირე ტერიტორიაზე აერთიანებს მოწყობილობებს, მაგალითად, სახლში, სკოლაში ან ოფისში

LAN-ში შეიძლება გამოიყენებოდეს: კომპიუტერები და ლეპტოპები - პრინტერები - სერვერები - Switch - Router - Wi-Fi Access Point და ქსელის კაბელები

Switch აკავშირებს ერთ ლოკალურ ქსელში არსებულ მოწყობილობებს და Ethernet კადრებს (Frames) საჭირო მოწყობილობისკენ აგზავნის. ამისთვის ის ძირითადად MAC Address-ებს იყენებს

Router აკავშირებს სხვადასხვა IP ქსელს და პაკეტებს ერთი ქსელიდან მეორეში გადაამისამართებს. მაგალითად, სახლის როუტერი სახლის LAN-ს ინტერნეტთან აკავშირებს

მოკლედ: Switch - მოწყობილობებს ერთ LAN-ში აკავშირებს - Router - სხვადასხვა ქსელს ერთმანეთთან აკავშირებს


3. OSI Model — 7 ფენა

OSI Model არის მოდელი, რომელიც ქსელურ კომუნიკაციას შვიდ ფენად ყოფს. თითოეულ ფენას თავისი დანიშნულება აქვს

7.  Application (აპლიკაციის ფენა) მომხმარებლის პროგრამებს ქსელურ
    სერვისებთან მუშაობის საშუალებას აძლევს. მაგალითები: HTTP, HTTPS, DNS

6.  Presentation (წარმოდგენის ფენა) მონაცემების წარმოდგენას,
    ფორმატირებას, დაშიფვრასა და შეკუმშვას უკავშირდება. მაგალითები:
    ტექსტის კოდირება, JSON-ის ფორმატი და მონაცემების დაშიფვრა. შენიშვნა:
    რეალურ TCP/IP ქსელებში ეს ფუნქციები ყოველთვის ცალკე ფენად არ არის გამოყოფილი

5.  Session (სესიის ფენა) მართავს კომუნიკაციის სესიების შექმნას,
    შენარჩუნებასა და დასრულებას. მაგალითი: ორ სისტემას შორის ხანგრძლივი
    კომუნიკაციის სესიის მართვა. შენიშვნა: თანამედროვე ქსელებში ამ ფენის
    ფუნქციები ხშირად სხვა ფენებშია განაწილებული

4.  Transport (ტრანსპორტის ფენა) მართავს პროგრამებს შორის მონაცემების
    გადაცემას, პორტებს და საჭიროების შემთხვევაში მონაცემების სწორ
    თანმიმდევრობასა და ხელახლა გადაცემას. მაგალითები: TCP და UDP. TCP
    უზრუნველყოფს საიმედო და თანმიმდევრულ გადაცემას; UDP უფრო მარტივი გადაცემის მეთოდია

3.  Network (ქსელის ფენა) უზრუნველყოფს სხვადასხვა ქსელებს შორის
    პაკეტების მარშრუტიზაციას და IP მისამართების გამოყენებას. მაგალითები:
    IP და როუტერის მიერ პაკეტის მიმართულების არჩევა

2.  Data Link (მონაცემთა არხის ფენა) მონაცემებს კადრებად (Frames) აწყობს
    და ერთი ლოკალური ქსელის მონაკვეთში გადაცემას უზრუნველყოფს. ამ ფენაზე
    ხშირად გამოიყენება MAC Address. მაგალითები: Ethernet, Wi-Fi-ის არხის დონის ფუნქციები და Switch

1.  Physical (ფიზიკური ფენა) გადასცემს ბიტებს ფიზიკური სიგნალების სახით.
    მაგალითები: Ethernet კაბელი, ოპტიკურ-ბოჭკოვანი კაბელი და Wi-Fi რადიოსიგნალი

Application -> Presentation -> Session -> Transport -> Network -> Data Link -> Physical


4. Packet და Frame

Packet არის ქსელური მონაცემების ერთეული, რომელიც OSI მოდელის
ქსელის ფენასთან (Layer 3) არის დაკავშირებული. IP პაკეტი შეიცავს
ინფორმაციას, მაგალითად, წყაროსა და დანიშნულების IP მისამართებს

Frame არის მონაცემთა არხის ფენის (Layer 2) ერთეული. Ethernet
Frame შეიცავს MAC მისამართებს და მონაცემებს, რომლებიც ლოკალური ქსელის მონაკვეთზე გადაიცემა

მთავარი განსხვავება:
Packet - Layer 3-ს უკავშირდება და IP მისამართებს იყენებს
Frame - Layer 2-ს უკავშირდება და MAC მისამართებს იყენებს

ქსელში packet-ი ხშირად მოთავსებულია frame-ის შიგნით. სხვადასხვა ქსელურ
მონაკვეთზე გადასვლისას frame-ი შეიძლება შეიცვალოს, ხოლო IP packet-ი
ჩვეულებრივ აგრძელებს გზას დანიშნულებისკენ


5. DNS

DNS (Domain Name System) არის სისტემა, რომელიც დომენის სახელებს  შესაბამის IP მისამართებთან აკავშირებს

DNS საჭიროა, რადგან ადამიანებისთვის google.com-ის მსგავსი სახელების დამახსოვრება უფრო მარტივია, ვიდრე IP მისამართების

როგორ მუშაობს: 
1. მომხმარებელი ბრაუზერში წერს დომენის სახელს, მაგალითად: example.com 
2. მოწყობილობა ამოწმებს, ხომ არ აქვს მისამართი უკვე შენახული ქეშში 
3. თუ მისამართი შენახული არ არის, მოწყობილობა DNS Resolver-ს მიმართავს 
4. Resolver საჭიროების შემთხვევაში სხვა DNS სერვერებს ეკითხება და შესაბამის IP მისამართს პოულობს 
5. IP მისამართი უბრუნდება მოწყობილობას, რომელსაც შემდეგ სერვერთან დაკავშირება შეუძლია

DNS დომენის სახელს IP მისამართთან აკავშირებს ის თავად ვებგვერდის მთელ შიგთავსს არ აგზავნის


6. HTTP და HTTPS Request და Response

HTTP (Hypertext Transfer Protocol) არის პროტოკოლი, რომელსაც ბრაუზერი და ვებსერვერი ვებრესურსების გაცვლისთვის იყენებენ

HTTPS არის HTTP, რომელიც TLS-ის საშუალებით დაშიფრულ კავშირს იყენებს. ეს
ამცირებს იმის რისკს, რომ მესამე პირმა გადაცემული მონაცემები წაიკითხოს ან
შეცვალოს, და ეხმარება სერვერის ნამდვილობის შემოწმებას.

რატომ არის HTTPS უფრო უსაფრთხო: 
- მონაცემები გადაცემისას დაშიფრულია
- კავშირის მთლიანობა მოწმდება, რათა ცვლილებების აღმოჩენა შესაძლებელი იყოს
- TLS სერტიფიკატი ბრაუზერს სერვერის იდენტობის შემოწმებაში ეხმარება

HTTP Request (მოთხოვნა) არის შეტყობინება, რომელსაც კლიენტი სერვერს
უგზავნის. ის შეიძლება შეიცავდეს მეთოდს, მისამართს, სათაურებს და ზოგჯერ
მონაცემების სხეულს. მაგალითი: ბრაუზერი სერვერს კონკრეტული გვერდის მიღებას სთხოვს.

HTTP Response (პასუხი) არის სერვერის პასუხი. ის შეიცავს სტატუსის კოდს,
სათაურებს და ხშირად მონაცემების სხეულს. მაგალითი: სერვერი აბრუნებს HTML
ფაილს ან შეცდომის კოდს, მაგალითად 404 Not Found

ხშირი HTTP მეთოდები: 
- GET - რესურსის მიღება
- POST - მონაცემების გაგზავნა ან ახალი რესურსის შექმნის მოთხოვნა

მნიშვნელოვანია: HTTPS არ ნიშნავს, რომ ვებსაიტი აუცილებლად სანდოა ის ძირითადად კავშირის დაცვას უზრუნველყოფს


7. როგორ მუშაობს Website

როდესაც მომხმარებელი ბრაუზერში ვებსაიტის მისამართს წერს, ჩვეულებრივ შემდეგი პროცესები ხდება:

1. ბრაუზერი ამოწმებს, აქვს თუ არა საჭირო ინფორმაცია უკვე შენახული
2. DNS-ის საშუალებით პოულობს დომენის შესაბამის IP მისამართს
3. ბრაუზერი სერვერთან კავშირს ამყარებს. HTTPS-ის შემთხვევაში, ჩვეულებრივ, TLS კავშირიც მყარდება
4. ბრაუზერი აგზავნის HTTP Request-ს
5. სერვერი ამუშავებს მოთხოვნას და აბრუნებს HTTP Response-ს
6. პასუხში შეიძლება იყოს HTML, CSS, JavaScript, სურათები ან სხვა რესურსები
7. ბრაუზერი HTML-ს კითხულობს, CSS-ით გვერდის გარეგნობას აყალიბებს და JavaScript-ს საჭირო მოქმედებების შესასრულებლად იყენებს
8. საჭიროების შემთხვევაში ბრაუზერი დამატებით მოთხოვნებს აგზავნის სურათების, შრიფტებისა და სხვა ფაილების მისაღებად

HTML, CSS და JavaScript-ის როლები:

HTML (HyperText Markup Language) გვერდის სტრუქტურას და შინაარსს განსაზღვრავს: სათაურებს, აბზაცებს, ბმულებს, სურათებსა და ფორმებს

CSS (Cascading Style Sheets) გვერდის გარეგნობას განსაზღვრავს: ფერებს, ზომებს, განლაგებას, შრიფტებსა და ეკრანის სხვადასხვა ზომაზე მორგებას

JavaScript გვერდს ინტერაქტიულობას და დინამიკურ ქცევას ამატებს: ღილაკებზე რეაგირებას, ფორმების შემოწმებას, მენიუების გახსნას და სერვერიდან მონაცემების მიღებას


8. პროცესის მარტივი სქემა

Browser 
1. მომხმარებელი წერს დომენის სახელს DNS 
2. აბრუნებს სერვერის IP მისამართს Server 
3. Browser აგზავნის HTTP/HTTPS Request-ს 
4. Server აბრუნებს HTTP/HTTPS Response-ს HTML / CSS / JavaScript
